# 01｜产品规格：AdFlow Console

## 1. 产品定位

AdFlow Console 是独立的 Meta 广告运营工作台，服务于需要同时管理一个或多个广告账户的运营人员。它使用 Meta 官方 Marketing API，在账户授权和应用权限范围内读取、创建和修改广告对象。

产品重点：

- 比官方后台更清楚的中文信息架构。
- 更快的账户切换、筛选、批量操作和报表。
- 明确展示数据新鲜度、权限状态和同步错误。
- 通过 Demo Provider 让研发、测试和演示不依赖真实 Meta 凭证。

产品不得暗示 Meta 官方背书，也不得突破 Meta 授权、隐私、审核或限流边界。

## 2. 用户角色

| 角色 | 权限 |
|---|---|
| Owner | 组织、成员、连接、读写、导出、审计全部权限 |
| Admin | 账户连接、广告读写、报表、成员查看；不能删除组织 |
| Operator | 查看与编辑广告、创建草稿、在具备写权限时发布 |
| Analyst | 只读广告与报表、保存视图、导出 |
| Viewer | 只读看板和广告表格，不可导出敏感明细 |

权限采用明确 action：

```text
org:manage
member:read
member:write
connection:read
connection:write
ads:read
ads:write
reports:read
reports:export
audit:read
```

## 3. 核心用户任务

### 3.1 首次使用

1. 用户登录应用。
2. 创建或加入组织。
3. 选择“连接 Meta”或“使用演示账户”。
4. OAuth 返回后展示已授予 scope、可访问广告账户和连接有效期。
5. 用户勾选要纳入工作区的广告账户。
6. 系统进入后台同步，先允许查看账户骨架和同步进度。
7. 同步完成后进入总览。

### 3.2 日常监控

1. 选择广告账户和日期范围。
2. 查看 KPI 与趋势。
3. 查看异常：花费激增、无转化、同步失败、Token 临期。
4. 进入 Campaign 表格，筛选和排序。
5. 打开右侧详情抽屉查看分日趋势、对象配置和最近修改。

### 3.3 批量管理

1. 在 Campaign / Ad Set / Ad 任一层级勾选对象。
2. 使用固定批量操作栏执行启用、暂停或预算修改。
3. 系统显示影响对象数、权限和风险说明。
4. 用户确认后提交后台任务。
5. 行状态显示“处理中”，完成后展示逐项结果；部分失败不回滚成功项，但必须可导出失败明细。

### 3.4 创建广告

1. 点击“新建广告”。
2. Step 1：Campaign 名称、目标、特殊广告类别、预算方式。
3. Step 2：Ad Set 转化位置、优化目标、预算、排期、受众、版位、归因。
4. Step 3：身份、格式、素材、文案、链接、CTA、追踪参数。
5. Step 4：统一审核，显示警告、预览、费用和权限状态。
6. 保存草稿或发布到 Meta。
7. 发布后显示每个对象的 Meta ID 和失败定位。

创建流程必须允许只保存草稿；不得要求用户一次填完。

### 3.5 自定义报表

1. 选择账户、日期、粒度、层级。
2. 选择指标和允许的 breakdown。
3. 预估查询规模；小查询同步，大查询异步。
4. 结果以表格和折线图展示。
5. 保存为报表预设或导出 CSV。

## 4. MVP 范围

### 必须交付

- 用户登录、组织和角色。
- Meta 连接与演示模式。
- 多广告账户选择。
- Overview 总览。
- Campaign / Ad Set / Ad 三级列表。
- 基础对象字段与 Insights 指标合并展示。
- 搜索、筛选、排序、分页、列管理、保存视图。
- 详情抽屉。
- 单个和批量启停；真实写入受开关保护。
- 创建向导和草稿。
- 图片/视频素材列表与上传流程骨架。
- 广告预览。
- 自定义报表与 CSV。
- 同步中心、错误中心和审计日志。
- Demo Provider、自动化测试和部署文档。

### Phase 2 以后

- 自动规则的真实执行。
- AI 文案或预算建议。
- Lead 数据或 CRM 同步。
- 跨渠道归因。
- 多品牌白标。
- 移动端完整编辑。
- 高级受众管理。
- 竞品广告情报。

## 5. 关键业务规则

1. **只读优先**：生产默认不允许 Meta 写操作。
2. **账户隔离**：所有查询必须带 organizationId 和 adAccountId，服务端再次校验归属。
3. **币种隔离**：不同币种不能直接合计；跨账户看板按币种分组。
4. **时区明确**：日期过滤和日粒度报表按广告账户时区；UI 显示时区。
5. **数据新鲜度**：每个页面显示最新对象同步和 Insights 同步时间。
6. **非原子批量操作**：逐项结果可追踪，部分失败必须清楚显示。
7. **状态区分**：同时展示 configured status 与 effective status，避免“用户设为启用但实际未投放”的误解。
8. **指标可配置**：主转化事件按账户设置，不把 purchase 写死为所有业务唯一转化。
9. **演示数据隔离**：演示连接和真实连接不得混合汇总。
10. **写入前确认**：预算、状态、删除/归档、发布均需要影响摘要和确认。

## 6. 成功指标

| 指标 | MVP 目标 |
|---|---|
| 首页可交互时间 | 本地/典型部署下 P75 < 2.5 秒，数据区可渐进加载 |
| 表格操作反馈 | 本地筛选/选择 < 100ms；服务端操作立即进入处理中状态 |
| 同步可恢复性 | Worker 重启后可从 checkpoint 继续，不重复写入 |
| 数据正确性 | 样例报表与 Meta 返回原始值逐字段对账一致 |
| 错误可定位性 | 所有失败有内部 requestId；Meta 错误可关联 fbtrace_id |
| 安全 | 浏览器、日志、构建产物中不存在真实 Access Token |
| 可访问性 | 核心流程达到 WCAG 2.2 AA 基础要求，无严重 axe 问题 |

## 7. 非功能要求

- 生产可横向扩展 Web 与 Worker。
- 数据库迁移可回滚或提供明确修复方案。
- Meta API 不可用时，已同步数据仍可只读浏览。
- 所有关键任务具备幂等键、重试策略和最终状态。
- 关键列表支持至少 10,000 个对象的服务端分页，不全量传到浏览器。
- CSV 导出在 Worker 中生成，避免阻塞 Web 请求。
- 保留审计日志至少 180 天；具体可配置。
